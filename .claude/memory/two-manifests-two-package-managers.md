# Two manifests, two package managers (verified 2026-08-28)

| | `1. App/package.json` (`pog-e7-optimizer`) | `1. App/2. Frontend/1. Source/package.json` (`poge7optimizer`) |
|---|---|---|
| Role | build/tooling package: Electron, webpack, babel, eslint, electron-builder config, all `scripts` | runtime/renderer deps that ship inside the packaged app |
| Manager | **Yarn 4** (`packageManager` pin, `yarn.lock`, `.yarnrc.yml` `nodeLinker: node-modules`) | **npm**, only through `1. Master/2. PS1/install_frontend.ps1` (`--ignore-scripts --legacy-peer-deps`) |
| Lockfile | `yarn.lock`, committed | none — the installer deletes `package-lock.json` on purpose; `node_modules/.package-lock.json` is npm's internal state |
| Coupling | `postinstall` → `electron-builder install-app-deps` and `electron-rebuild --module-dir "2. Frontend/1. Source"` both act on the inner tree; `build.files` ships the inner `node_modules/**` | `installedTransitives` is documentation-only, regenerated by `4. Both/2. Build/1. Scripts/regen-installed-transitives.js`; `overrides` is npm-only syntax |

This is the electron-react-boilerplate "two package.json" pattern. It is **not** frontend + backend:
the backend is Java — `3. Backend/1. Source/3. XML/pom.xml` → `1. Master/3. Jar/backend.jar`, shipped
via `build.extraFiles`. There is no package.json under `3. Backend/`.

**Why it matters:** `--legacy-peer-deps` means npm never fails a peer conflict at install time, so
peer checks on the inner manifest are by hand; and because the outer `yarn install` writes into the
inner tree, the inner manifest must be finalized *before* the outer install runs.
`.claude/hooks/guard-package-root.mjs` denies the wrong-manager-in-wrong-root mistake.

**Renderer manifest has no persistent lockfile by design** (confirmed 2026-08-28): since
`install_frontend.ps1` deletes `package-lock.json` after install, the durable transitive record is
an inert `installedTransitives` field inside the renderer's own `package.json` (npm ignores it —
don't hand-edit the version numbers, it does nothing). It's auto-regenerated by
`4. Both/2. Build/1. Scripts/regen-installed-transitives.js`, which `install_frontend.ps1` runs after
a successful install (rebuilds the snapshot from `node_modules`, preserves EOL, stays
prettier-clean); can also be run standalone. `webpack.config.base.js` separately derives its
`externals` list from the renderer manifest's real `dependencies` (not `installedTransitives`).

**`install_frontend.ps1` never touches the outer tree** (a 2026-06 outer `@babel/core` bump looked
"up to date" after running it). For an outer *toolchain-only* bump (babel/eslint/webpack/prettier),
`yarn install --mode=skip-build` syncs `1. App/node_modules` without the slow `postinstall` native
rebuild (`electron-builder install-app-deps`); drop the flag when a native/runtime dep changed or
before packaging.

**How to apply:** edit inner → run `install_frontend.ps1` → edit outer → `yarn install` → `yarn lint`,
`yarn typecheck`, `yarn build`. Consider collapsing to one Yarn manifest during the reorg;
