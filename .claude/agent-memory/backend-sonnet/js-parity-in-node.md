- Real JS runs in Node without jQuery: read `damageCalc.js`, replace the `import HeroData` line with a stub and `export default` with a global assignment, run via `new Function`. Slice `processHeroSkill` out of `heroData.js` by text and apply it to `6. JSON/2. CACHE/cache/herodata.json` first: Java is sent the post-processed option arrays, not the raw file.
- A full sweep (every hero x every option) is ~5400 cases; Java side via a single-file `java -cp <javac out dir>;<shaded jar> Probe.java`. The repo fixture `10. Tests/damageMultipliersParity.json` is a small cut of it; no generator is in the repo (scripts were in the session scratchpad).
- Parity held for null and fully populated options; stale/empty effect names and partial skillOptions diverged until B37 (2026-10-30), which fixed both. Sweep recipe: `gen-parity.mjs all` (adds unknown/empty/partial cases) then `ParityProbe.java`; after B37 the only remaining diffs are the nine fields Java never reads (atkDiffPen family, constantValue, ...), so count only those. The repo fixture carries the "b37 " cases, generated by appending to it with the real JS (the fixture's own `skills` must equal processHeroSkill output; check it).
- Throwing run for tests (post-B37): partial skillOptions no longer throw. A stored hero whose `HeroSkills` has S1 but no S2/S3 (`setSkills(HeroSkills.builder().S1(..).build())`, skillOptions null) still passes `hasSkillData()` and makes `applyDamageMultipliers` throw after the db went live.
